RepoLens Engineering Journal
============================

Project objective
-----------------
Build RepoLens, a production-oriented codebase intelligence system that accepts
a public GitHub URL, safely indexes source code, detects repository structure,
supports hybrid retrieval, and returns grounded explanations with file/line
citations. The portfolio goal is to demonstrate more than a generic “chat with
code” interface: static analysis, information retrieval, local inference,
evaluation, observability, and regression testing should be visible in the
implementation.

Journal conventions
-------------------
Each entry records: the intended outcome, implementation decision, rationale,
action taken, observed result, and follow-up. This is an engineering record, so
it includes failed setup attempts and design tradeoffs. It records useful
decision rationale and reproducible facts, not hidden model reasoning.

2026-08-09 — Backend implementation
-----------------------------------
Safe ingestion:
  Implemented strict canonical GitHub HTTPS URL parsing. Embedded credentials,
  query strings, fragments, ports, alternate hosts, and non-root repository
  paths are rejected. GitHub DNS is checked against private, loopback,
  link-local, and reserved address ranges as an SSRF defense. Cloning is shallow,
  single-branch, blob-filtered, no-tag, time-limited, and performed in a temporary
  directory that is removed afterward. The repository's code is never executed.

File policy:
  Added limits of 4,000 files, 35 MB total indexed text, and 750 KB per file.
  Dependencies, build output, virtual environments, caches, binaries, media,
  lockfiles, credential-like filenames, and symlinks are excluded. Files must
  resolve inside the temporary clone and decode as UTF-8.

Static analysis:
  Added language detection for common backend, frontend, systems, data, and
  configuration formats. Python uses the standard-library AST to extract
  imports, classes, functions, and exact line ranges. Other languages use a
  deterministic structural splitter around common declaration forms, with
  bounded file-section chunks as coverage fallback.

  Added deterministic extraction for:
  - imports and module dependencies;
  - functions/classes/interfaces and other symbols;
  - FastAPI/Flask-style decorators and Express-style HTTP routes;
  - entry-point conventions and executable markers;
  - framework/technology signals from manifests;
  - file roles such as interface, route, service, model, authentication, test,
    configuration, and documentation;
  - file importance based on role, entry-point markers, manifests, symbols,
    imports, inbound references, and test penalties;
  - recommended reading order and an evidence-linked architecture map.

Retrieval decision:
  Implemented a zero-dependency hybrid retriever. One ranking uses BM25 term
  statistics. The second uses normalized hashed token vectors as a deterministic
  local semantic proxy. Reciprocal-rank fusion combines both lists, then path and
  symbol overlap provide a lightweight reranking signal.

Tradeoff:
  Hashed vectors do not provide the semantic quality of a transformer embedding
  model or a learned cross-encoder. They make the baseline fast, offline, and
  testable on any laptop. The interfaces are intentionally isolated so a
  sentence-transformer embedding model and cross-encoder can replace the local
  proxy in the next production phase without changing the API.

Full ML retrieval path added during final scope review:
  A review against the original brief identified that leaving learned retrieval
  only as a future interface would undersatisfy the explicit embedding/FAISS and
  cross-encoder requirements. Added an optional production path using
  sentence-transformers/all-MiniLM-L6-v2 embeddings, a FAISS inner-product index
  over normalized vectors, and cross-encoder/ms-marco-MiniLM-L-6-v2 reranking.
  Set REPOLENS_ML_ENABLED=1 after installing backend/requirements-ml.txt to use
  this path. The models download from Hugging Face on first use.

  The dependency-free BM25 + hashed-vector path remains the default because it
  starts instantly, works offline, and keeps CI deterministic. This is explicit
  in the interface, README, environment example, and code; benchmark claims must
  name which retrieval configuration produced them.

Determinism correction found by repeated evaluation:
  A subsequent evaluation run produced the same perfect Recall@3 but MRR fell
  from 1.0 to 0.667. Investigation found that the fallback vectorizer used
  Python's built-in hash(), whose per-process random seed can change vector
  collisions and therefore ranking order. Replaced it with a stable BLAKE2b
  token digest mapped into 384 dimensions. This makes CI comparisons meaningful
  across processes and machines rather than merely repeatable within one process.

Grounded answer policy:
  The service retrieves evidence before generation. If retrieval confidence is
  below a threshold, it returns the exact refusal required by the specification.
  When Ollama is reachable, the prompt forbids unsupported claims and invented
  citations. If Ollama is missing, times out, or produces an answer without a
  citation marker, RepoLens returns a deterministic extractive answer from the
  top code chunks. This makes missing local-model infrastructure a graceful
  degradation rather than a product failure.

Persistence and observability:
  SQLite stores the full analysis/chunk payload. Each question stores retrieved
  file/line ranges and scores, latency, and whether it answered or refused. WAL
  mode supports safer concurrent local reads/writes.

2026-08-09 — Q&A relevance failure shown in screenshot
-------------------------------------------------------
Observed failure:
  The authentication example returned unrelated symbols from aiGuessEval.js,
  gameDataStore.js, and gestureDetection.ts. The answer repeated “strongest
  evidence” three times even though none of those snippets described auth.

Root cause:
  Reciprocal-rank fusion assigned a positive rank score to every top candidate,
  including documents whose BM25 score was exactly zero. The offline hashed
  vector fallback could also collide unrelated words into the same numeric
  dimension. The final 0.006 evidence threshold therefore measured ranking
  position rather than actual topical support and allowed fabricated relevance.

Fix design:
  Added conservative code-domain query expansion for authentication, databases,
  API endpoints, and contributor-orientation questions. Removed filler words
  from queries. Zero-score BM25 candidates are now discarded, and the offline
  hashed-vector fallback may rank only documents sharing a meaningful original
  or expanded concept term. When an authentication question has no credible
  evidence, RepoLens now explicitly says it found no auth flow, routes,
  middleware, session/token handling, or login implementation, with no fake
  citations. Traces treat any answer without citations as a refusal.

Regression coverage added:
  1. the exact three unrelated screenshot-style chunks return no evidence for
     “Where does authentication happen?”;
  2. database questions expand to persistence/storage vocabulary and retrieve
     the data store;
  3. missing authentication evidence produces an honest, citation-free answer.

2026-08-09 — Product proposal for painful repository setup
----------------------------------------------------------
Problem statement:
  Setup instructions alone do not prevent onboarding failures. Contributors can
  still encounter missing environment variables, incompatible runtime versions,
  lockfile/manifest drift, undocumented Redis or database requirements, occupied
  ports, and operating-system-specific commands.

Proposed RepoLens solution:
  Add a “Setup readiness” report generated through static analysis. It should
  inventory required runtimes and version constraints, identify the package
  manager and canonical commands, extract environment-variable names without
  reading or displaying secret values, classify external services as required
  or optional, identify expected ports, flag platform-specific scripts, and
  compare package manifests with lockfiles. Every claim should cite the exact
  configuration or source file that established it.

Output design:
  Present a readiness status (Ready, Needs attention, or Blocked), followed by
  blockers, warnings, optional enhancements, a copyable ordered setup sequence,
  and exact remediation text. For Moodle, the report would explain that Node and
  npm are required; PostgreSQL, Redis, and external AI providers are optional;
  `.env.example` defines configuration; and the game retains fallback behavior
  when optional services are absent.

Safety boundary:
  Keep the default diagnostic read-only so RepoLens maintains its “never executes
  repository code” guarantee. A future sandboxed verification mode could run
  install or health checks only after explicit opt-in, but that is a separate
  capability and should not be implied by the static readiness report.
